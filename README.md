# 灵感映像｜对标生图助手

**学员只要先上传对标图片，一句话不说，也能开始。** 助手先逐张解析并归类风格，再主动引导上传自家产品、补充已知信息和生成图片。无需输入技能名称、启动口令或固定提示词。

支持多种风格，不固定成日系。首期只用 LibTV 生图。

版本：0.3.1。适合 WorkBuddy，也可在兼容 `SKILL.md` 且能看图、执行本地命令的宿主使用。

## 本版重点更新

0.3.1 修复安装包被 `.gitignore` 拦截的问题；保留 0.3.0 的中文排版和完整页面设计规则，LibTV 生图渠道不变。

- **中文重新设计**：按中文语义断行，选择契合主题的字形、笔画重量和配色，不默认套纯黑极粗满宽标题，不照抄英文刊头。
- **分析真正落到画面**：先确定封面、专题页等页面类型，再把关键风格逐条映射到实际提示词和成图区域。
- **完整页面交付**：需要文字的页面不能只交底图；分阶段制作须继续完成排版，工具不足就明确未完成。
- **逐版复核**：修标题不能掩盖上一版产品、印花、手部等问题；未解决项持续保留。

新规范是对助手的设计和验收要求，不是新增字体引擎；实际改善还需要用成图验证。具体见 [中文排版](references/chinese-typography.md) 与 [页面设计](references/art-direction.md)。

## 能做什么

| 学员给的资料 | 技能怎么处理 |
| --- | --- |
| 只上传一张或多张对标图，不说话 | 立即逐图解析，记录证据位置、判断理由与置信度，再分组并引导上传产品 |
| 产品图＋完整参数 | 锁定款式、结构、配色、图案及准确文案，进入精准模式 |
| 产品图，参数不知道 | 按可见外观创作，场景和排版自由设计，不编造产品事实 |
| 指定人物照片 | 增加人物特征锁定和成图对照检查 |
| 只想分析或要提示词 | 交付分析与提示词，不上传、不生图 |
| 明确说直接生成 | 先给简短创意摘要，然后接着执行，不多问一轮 |

生图前给短摘要，生图后检查产品、人物、文字与参考风格。无法验证的部分会明确标注。技能提高可追溯性和约束完整性，不承诺每次生成都能完全还原。

## 安装到 WorkBuddy

[下载 0.3.1 完整安装包](https://github.com/pengdi190721-dot/visual-reference-product/releases/download/v0.3.1/visual-reference-product-0.3.1.zip)。

推荐用界面导入：打开「专家·技能·连接器」→「技能」→「添加技能」→「上传技能」，选完整技能压缩包。入口以当前版本为准，见 [WorkBuddy 官方技能说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。不要只上传 `SKILL.md` 而漏掉配套文件。

已有旧版时，先备份自行修改过的内容，再在界面使用可用的替换入口；若不支持替换，可移除旧技能后导入新版，避免同时启用两个同名副本。由使用者自行操作，本包不会自动修改已安装技能。0.3.1 安装包已排除 `.gitignore`，许可证以 `LICENSE.md` 保留。旧包中的 `.gitignore` 可能直接导致提交失败，不能假定界面一定会自动跳过。请下载发布页提供的安装包，不要使用仓库的源码下载包；源码包含仓库管理文件。

也可以在解压后的技能目录运行本地安装脚本：

```sh
python3 scripts/install.py
python3 scripts/install.py --check
```

Windows：

```powershell
py -3 scripts/install.py
py -3 scripts/install.py --check
```

脚本默认复制到用户目录的 `.workbuddy/skills/visual-reference-product/`，不覆盖已有版本。安装并启用后，新开 WorkBuddy 会话，先上传对标图片即可。文件校验通过不代表界面一定已启用；若未出现，使用官方「上传技能」入口导入，并检查已安装列表的开关。

项目共享可用 `.codebuddy/skills/`，这是 [WorkBuddy 官方项目配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project) 支持的路径。可通过 `--skills-dir` 指定目标，不要在同一个范围装多个同名副本。

## 首次使用需要准备

1. WorkBuddy 能实际看到上传图片。
2. 本机有 Python 3.9 以上和官方 LibTV 命令行工具，并完成自己的账号登录。
3. 先上传对标图，不必同时准备产品图或填写参数。助手会逐步引导后续操作。
4. 到生图阶段再确定 LibTV 画布；没有画布时，由助手引导选择工作区并新建专用画布，不阻塞前面的看图分析。

环境只读检查：

```sh
python3 scripts/libtv_adapter.py doctor
```

安装渠道与执行细节见 [LibTV 适配规范](references/libtv.md)。本包不附带第三方工具、登录信息或生图额度。实际调用可能消耗账号额度，价格以用户账户与当前模型为准。

## 学员实际怎么用

| 步骤 | 学员只需做什么 | 助手会做什么 |
| --- | --- | --- |
| 1 | 上传喜欢的对标图片，可以什么都不说 | 立即逐张拆解，记录证据与置信度，整理风格组 |
| 2 | 按助手提示上传自己的产品照片 | 提取可见外观，锁定款式、颜色和细节 |
| 3 | 回答自己知道的参数；不知道就直说不知道 | 集中问一次，不反复追问，不编造事实 |
| 4 | 看简短创意摘要，想出图就自然回复“生成” | 通过 LibTV 生成，再检查产品、人物与文字是否准确 |

如果已经说过“直接生成”，助手展示摘要后就接着执行。只发对标图时先做分析，不直接扣费。只需要分析时说“只分析”即可。

产品信息可以像这样补充，知道多少填多少，不是启动流程所必需：

> 我的产品是：21寸三折伞，软萌治愈系。尺寸：53*8K；布料：黑胶布；伞架：铁架；包装：OPP；货号：HZZ2607；功能：黑胶防晒，轻巧便利。

初次只发图片默认按对标处理，不猜“最后一张是产品”。在助手已经邀请上传产品之后，再发来的图片按产品接收；明确说“补充对标”则继续追加参考。助手维护当前阶段，学员不用重说整套流程。

## 验证与限制

```sh
python3 -m unittest discover -s tests -v
```

脚本会校验来源引用、素材映射、模型能力、生成授权记录和防重复提交，但不能自动证明看图判断正确。每张成图仍需由能看图的宿主逐项检查。模糊图、遮挡、多图风格冲突、中文小字、产品细节漂移都可能影响结果。

“只传图片开始”已写入技能触发描述和执行规则。实际自动调用仍取决于宿主是否启用了技能、能否读取图片以及是否加载该技能；本包不会修改 WorkBuddy 的全局规则。0.3.1 尚未完成在 WorkBuddy 中的纯图片消息及真实生图复测，详见验证记录；规范更新和自动化测试不能证明成图已经变好看。

生成失败或中断时，先查原节点，不直接重新跑一遍。默认只尝试一次生成；额外尝试按用户已授权的数量或重试预算执行。

## 公开发布准备

本目录可作为独立仓库内容，已附忽略规则、MIT 许可证、测试和中文说明。发布包不应包含学员图片、原始聊天、运行记录、账号凭据或生成结果。本项目代码与规范的许可不替用户素材授予使用权。

本地制作和验证不会自动创建仓库、提交或推送到 GitHub。只有用户明确指定仓库并授权后，才能执行发布操作。

需要重新打包时，在技能目录运行：

```sh
python3 scripts/package.py --output ../visual-reference-product-0.3.1.zip
```

同时会生成逐文件散列清单。打包器只纳入指定目录中的规范、模板、代码和测试，不打包运行目录、图片、缓存或环境配置。
