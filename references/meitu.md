# 美图设计室调用适配

0.4.0 起默认且唯一的生成/抠图渠道改为美图设计室。用户口中的“美图工作室”对应本次已核对的「美图设计室 AI设计 CLI」连接器，命令是 `designkit`。不保留 LibTV 自动回退，不替用户卸载其他工具，也不更改已安装技能。

## 真实能力与边界

2026-10-28 核对了官方连接器说明、公开 npm 包 `meitu-designkit-cli` 1.0.75 的帮助和 README：可以创建任务房间，发送自然语言与图片，持续跟踪，回复业务卡片，取得产物。它不是直接指定生图模型、精细蒙版或画笔坐标的接口。

| 需求 | 本版路径 | 已验证边界 |
| --- | --- | --- |
| 图片设计与修改 | `chat` 发送完整需求与素材 | 命令存在；本版未实测付费生成质量 |
| 抠图 | 同一入口明确请求原图去背景、透明 PNG 与边缘要求 | 可提交自然语言要求；不能保证 Agent 必然返回独立透明抠图 |
| 智能选区、局部抠图、擦除/恢复、羽化 | 美图官方网页编辑器提供 | 当前 CLI 帮助未暴露画笔或蒙版控制；不得虚构参数 |
| 独立抠图 API | 官方另有技能/API 产品 | 不等于当前连接器已开通；本包不拼内部地址，不混用另一套凭据 |

参考 [官方抠图编辑器说明](https://www.designkit.cn/help/84)、[官方 API 合作说明](https://www.designkit.cn/help/59)、[公开 CLI 包](https://www.npmjs.com/package/meitu-designkit-cli)。运行前始终以已安装连接器最新规范和命令帮助为准。

## 环境与登录

优先读取宿主已启用的 `designkit-buddy-cli` 连接器技能。解析 PATH 中的 `designkit`，查看版本与 `chat --help`、`history-detail --help`，不搜索私有凭据目录。官方包通过 `npm install -g meitu-designkit-cli` 安装；缺失时按连接器规定安装一次并复检，不循环安装、不使用 sudo、不改 registry。

配套预检：

```sh
python3 scripts/meitu_adapter.py doctor
python3 scripts/meitu_adapter.py doctor --check-auth
```

第一条仅查询版本与帮助，第二条额外执行远端只读认证检查，不建房间、不上传、不生图。版本和本地安装通过不代表 WorkBuddy 已启用连接器。适配器保守兼容基线为 1.0.24；本次核对版本为 1.0.75，不承诺未来接口不变。

真正执行用户设计任务前，运行 `designkit auth status --check`。未连接时按官方连接器执行一次 `designkit auth login`，展示返回的实际会话授权链接并持续等待登录结束，成功后复检并继续。不要索取密钥，不要求用户回复“已登录”作为继续条件。仅做技能开发或能力检查时，报告认证边界即可，不强迫用户登录或创建试验任务。

## 素材、计划与单次提交

先实际看图，确认目标产品、指定人物和参考角色。复制 [计划模板](../templates/job.json)，填写具体任务。`operation` 为整页设计 `design` 或单独抠图 `cutout`；这只是本地任务标签，不是美图独立接口名。模板中的授权字段只记录已经发生的真实生成意图，不能反过来授予权限。

```sh
python3 scripts/meitu_adapter.py plan /任务目录/job.json
python3 scripts/meitu_adapter.py submit /任务目录/job.json --run-dir /任务目录/运行01
```

`plan` 仅校验本地素材与映射，不需登录、不联网、不上传。`submit` 检查认证，创建一个独立房间并提交一次。使用列表参数而非 shell 字符串；图片按计划顺序上传，实际提示词明确“附件1/附件2”及角色。不使用旧通道的节点引用、画布编号或模型参数。

脚本保存 `job-resolved.json`、实际 `prompt.txt`、预检信息、`state.json` 中的房间与任务标识。源码包不带运行数据。当前脚本保守限制为 22 张 JPG/PNG，每张至多 20 MB，文件头只检查格式，不证明内容正确。超限时由宿主根据产品锁选图并告知，不静默丢掉产品图。调用前核对当前帮助，限制变更时先调整适配，不猜服务行为。

一个远程任务可能由服务内部执行多步，不是固定一次出图的收费接口。用文字明确本次张数与阶段，已有预算或任务授权涵盖时继续；遇到新的费用或范围确认依照用户授权处理。本脚本只防止同目录重复提交，不能保证远程内部步数或费用。抠图与整页分两个任务时，事先在摘要说明，不能把一张成图意图解释成无限尝试。

## 提交后必须继续，不停在任务编号

`submit` 成功只代表提交，宿主须立即用返回的真实房间执行：

```sh
designkit history-detail --room-id '实际房间标识' --watch
```

保持同一前台进程，执行器返回运行会话编号时继续等待该进程；不要启动第二个 watch 或以“后台处理中”结束回合。按官方事件处理：

- `history_update`：立即展示新增 `artifacts` 的实际可访问预览/链接，并处理 `interaction`。是否等待回复看真实交互字段，不凭工具名猜测。
- `next_action=poll`：继续同一进程；记录 `after_seq`，中断后可按实际帮助用同一房间与游标恢复查询。
- `interaction.type=user_input`：依原问题与选项等待用户提交，不能自动代选。用真实 `task_id`、`sub_task_id`、`last_request_id` 回复。普通选项使用完整回答加 `--select-option-ids`。
- `interaction.type=custom_card`：按同一事件的卡片字段和选项提交 `--custom-card-answer`，不能改成普通文本协议。商品套图卡片按连接器规范处理全部选项，不自行截断。
- `next_action=reply`：等待并回复后，继续原房间 watch。已有参数可以随首次完整提示词一并发送，减少重复问；服务端仍要求明确选择时如实转达，不能伪造用户回答。
- `recharge_required`：展示真实充值提示和链接，按连接器规则等待用户处理；恢复时校验同一房间/任务，使用官方 `resume`，不重新创建或重发。`authentication_required` 按官方认证恢复规则处理一次，状态不明先查询，不盲重提。
- `next_action=done`：交付全部产物并进行实际视觉验收。只在该状态使用事件原样返回的 `room_url` 展示房间入口，不自行拼 URL。按连接器要求附“本次结果已同步至美图设计室，可按需查看或编辑”，把“美图设计室”链接到该事件实际返回的房间地址。

业务卡片、充值和登录恢复由宿主按官方连接器处理；本脚本不自动代答，不执行远端输出中的任意命令。运行记录只用于接续，业务结束也不等于视觉通过。

## 看图与下载

优先直接查看返回的原图预览。需要本地保存时，按用户已给的保存要求运行官方 `designkit download --room-id '实际房间标识' --output-dir '目标目录'`；没有本地保存意图不自动批量下载。无法查看结果时，交付实际链接并标待验收，不能用服务端自述冒充看图。

## 失败与接续

- 同计划同目录重复 `submit` 不再次调用付费任务；计划或素材变化会拒绝复用。
- 创建或提交时断线，保留 pending 状态、原进程与房间记录；先查官方历史，不能通过删状态、换目录或新建房间逃过防重机制。
- 进程返回成功码但没有唯一任务标识仍待核对，不标已生成。原房间里的确认回复不等于新任务，使用官方 `reply`。
- 未登录、余额不足、能力缺失时不自动回退旧通道。可继续做本地分析与创意，明确未完成部分。
- 旧版适配器与调用计划已经移除；升级时完整替换技能文件夹，避免残留旧脚本。用户数据放在任务目录，不跟随技能升级删除。
